### 정량 평가
- 맵은 Berlin이다. **랜덤 장애물 1개, 3개, 5개**로 각각 1회씩 주행한다.
- seed는 모든 팀이 같고, 공개되지 않는다.
- run 사이에 알고리즘이나 파라미터를 수정할 수 없다. 즉 **세 조건을 설정 하나로 주행**한다.
- 각 run은 **최대 3분 또는 최대 10바퀴**다.
- run마다 측정하는 값:
  - best lap time
  - lap count = **연속 무충돌 랩 수**
- "충돌"은 **충돌한 뒤 정지 상태로 남아 있는 모든 경우**를 뜻한다. 후진은 불가하다.
- 순위 계산:
  - final rank = (1·3·5개 각각의 time rank + count rank) 6개를 합한 값. 낮을수록 좋다.
  - 0랩이면 그 조건의 time rank는 최하위 공동 순위다.
  - count가 같으면 best lap time이 빠른 팀이 위다.

### 정성 평가 (감점·가점 요소)
- **주행 중 Ground Truth 사용은 감점**이다. 장애물 위치·크기, **자차 포즈** 등이 해당한다. Berlin 지도는 GT가 아니다. 학습 중에는 GT를 써도 된다.
- **IMU와 Odometer를 포함한 센서 토픽에 노이즈가 들어간다.** 크기는 비공개다.
- Perception 노드 코드를 개선하거나 새 알고리즘을 적용하면 평가에 반영된다.
- 플래너 1개와 제어기 1개(또는 신경망 1개)로 전체 레이스를 감당해야 한다. 근거 없는 MUX 구조는 감점이다.
- 구간별 하드코딩(좌표나 웨이포인트 인덱스 상수)은 **대폭 감점**이다.
- 기여도는 README와 git_commit_history.txt로 평가한다.
  - 리더·통합 역할은 가점이다.
  - 각자 본인 git 계정으로 커밋해야 한다.
  - 마감 직전 단일 커밋은 감점될 수 있다.
  - 공백·주석만 바꾼 커밋은 기여도에서 제외된다.

## 2. 지금까지의 가정과 달라진 점

| 지금까지 | 공지 | 영향 |
|---|---|---|
| 장애물 4개 고정으로 실험 | **1·3·5개** | 실험 조건 변경이 필요하다. 1개 조건은 속도 경쟁, 5개 조건은 완주 경쟁이 된다. |

| 실험 주행이 **`--pose-source gt`**(자차 포즈 GT) | **주행 중 GT 사용 감점** | **가장 큰 위험.** 지금까지의 모든 성적(36런, C1DC, CF1 등)이 GT 포즈 기준이다. pf 측위와 센서 노이즈 조건에서 성적을 다시 확인해야 한다. |
| 센서 노이즈 없음 | IMU·Odom에 노이즈 | 측위와 MPPI 상태 추정이 노이즈에 버티는지 확인해야 한다. 사용자가 계획한 "노이즈 내성" 순서가 확정 과제가 된다. |
| 후진 허용(11/19 사용자 확인) | "**후진 불가!!**" | 정지했다가 후진으로 빠져나오는 복구는 쓸 수 없다고 보는 게 안전하다. 우리 기준선은 이미 `reverse_recovery=false`다. 정확한 뜻(후진 자체가 금지인지, 후진해도 충돌로 처리되는지)은 조교 확인이 필요하다. |
| 교착(충돌 없이 정지) | "충돌 후 정지"만 충돌로 정의 | 충돌 없는 교착은 정의상 충돌이 아닐 수 있다. 하지만 3분 안에 랩이 쌓이지 않아 count와 time 모두 손해다. CF1처럼 "오래 멈춘 뒤 완주"는 실제로 손해다. |
| 성적 지표: 평균 랩·6랩 완주율 | **연속 무충돌 랩 수 + best lap**의 순위 합 | 평가 지표를 공지 방식으로 바꾼다. 조건 3개 × 2지표의 순위 합이다. 속도(time)와 안정성(count)의 비중이 같다. |
| 배율 0.8은 자체 목표 | 설정은 세 조건 공통 | 1·3·5개에 같은 배율과 파라미터를 써야 한다. 배율 스윕도 세 조건을 함께 봐야 한다. |

## 3. 이미 맞게 하고 있는 것
- 좌표·seed 특례와 구간별 하드코딩 금지는 이미 실험 규칙에 있다.
- 장애물은 인식 결과(`raw_obstacles`)를 쓴다. 시뮬 정답(`/sim/obstacles`)은 오프라인 대조에만 썼다. 다만 주행 경로에 GT가 없는지 코드 점검이 필요하다.
- 플래너·제어기는 MPPI 하나다. 그러나 MPPI 안의 PP 표본(`pp_fraction`), 그룹 계획, 쉴드가 "MUX"로 보이지 않도록 **논리적 근거를 설명할 준비**가 필요하다.
  - PP 표본은 표본 분포의 일부다.
  - 그룹 계획은 MPPI 비용의 기준 경로다.
  - 쉴드는 안전 필터다.
- Perception 개선(raw 확정 등)은 가점 요소다. 발표에서 강조할 수 있다.
- 커밋 작성자: 기준선 커밋(`3013bf9`~`1dc9dab`)은 사용자 계정(juwjang)으로 되어 있다. 첫 커밋 `835d06c`(misys:forza_pp 반입)는 작성자가 "Codex"다. 기여도 평가에서 어떻게 보일지 점검할 필요가 있다.
